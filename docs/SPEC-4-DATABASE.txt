LOCAL AI AGENT PLATFORM — BACKEND & DATABASE SCHEMA
Version: 1.0
Date: 2026-09-08

1. DATABASE
Primary database: PostgreSQL.

Use UUID primary keys.
Use UTC timestamps.
Use created_at and updated_at on mutable entities.
Use soft deletion only where business requirements justify it.

2. USERS
users
- id UUID PK
- email UNIQUE
- password_hash nullable
- display_name
- status
- email_verified_at
- created_at
- updated_at

3. SESSIONS
sessions
- id UUID PK
- user_id FK users.id
- refresh_token_hash
- expires_at
- revoked_at
- created_at

4. AGENTS
agents
- id UUID PK
- user_id FK users.id
- name
- device_name
- platform
- agent_version
- status
- last_seen_at
- revoked_at
- created_at
- updated_at

5. AGENT_SESSIONS
agent_sessions
- id UUID PK
- agent_id FK agents.id
- connection_id
- connected_at
- disconnected_at
- ip_hash or privacy-safe network metadata
- created_at

6. WORKSPACES
workspaces
- id UUID PK
- owner_id FK users.id
- name
- description
- created_at
- updated_at

7. PROJECTS
projects
- id UUID PK
- workspace_id FK workspaces.id
- name
- local_path_alias
- repository_url nullable
- default_branch nullable
- created_at
- updated_at

Do not store raw sensitive local filesystem paths unless required.

8. PROJECT_MEMBERS
project_members
- id UUID PK
- project_id FK projects.id
- user_id FK users.id
- role
- created_at

9. TASKS
tasks
- id UUID PK

- status

10. TASK_STEPS

- id UUID PK

- created_at

11. CONVERSATIONS
conversations
- id UUID PK
- project_id FK projects.id nullable
- user_id FK users.id
- title
- created_at
- updated_at

12. MESSAGES
messages
- id UUID PK
- conversation_id FK conversations.id
- role
- content
- model_id nullable
- token_input nullable
- token_output nullable
- created_at

Avoid storing secrets in message content.

13. TOOL_CALLS
tool_calls
- id UUID PK
- task_id FK tasks.id
- step_id FK task_steps.id nullable
- agent_id FK agents.id
- tool_name
- input_json
- output_json nullable
- status
- risk_level
- started_at
- completed_at
- error_code nullable
- created_at

Sensitive input/output should be redacted before storage.

14. APPROVALS

- risk_level

- status

- decided_at nullable
- expires_at
- created_at

15. AUDIT_LOGS
audit_logs
- id UUID PK
- user_id nullable
- agent_id nullable
- task_id nullable
- action
- resource_type
- resource_id
- metadata_json
- created_at

Audit records should be append-only from the application perspective.

16. PROVIDERS
providers
- id UUID PK
- name
- slug UNIQUE
- status
- config_json
- created_at
- updated_at

Never store plaintext provider secrets in normal application tables.

25. SECURITY DATABASE RULES
- Encrypt sensitive data.
- Hash passwords with a modern password hashing algorithm.
- Never store raw API keys in logs.
- Redact secrets from tool output.
- Enforce tenant/user ownership at every query boundary.
- Use database constraints and application authorization together.
- Maintain audit records for security-sensitive operations.
